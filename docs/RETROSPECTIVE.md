# Ретроспектива

Этот репозиторий - не попытка выдать старый код за современную архитектуру. Это снимок проекта, который решал реальную проблему в институте.

## Контекст

Расписание существовало как бумажная таблица и Excel-файл на сайте. Студентам нужно было быстро понимать, когда и где занятия, а изменения в расписании было трудно отслеживать. Система появилась как практический ответ на эту проблему.

Проект включал несколько частей:

- парсер Excel-файлов расписания;
- нормализованную MySQL-базу;
- PHP-сайт для просмотра расписания;
- экспорт данных для внешних клиентов;
- интеграции и эксперименты с ботами/уведомлениями.

## Что получилось хорошо

- Система решала реальную пользовательскую боль.
- Парсер работал с грязными Excel-файлами, которые не были рассчитаны на машинную обработку.
- Данные приводились к справочникам: группы, преподаватели, дисциплины, типы занятий, аудитории.
- Были добавлены дедупликация файлов по MD5 и пометка устаревших версий расписания.
- Часть запросов в C#-коде уже была параметризована.
- Появились тесты для ключевой эвристики распознавания ячеек.
- Баг-трекер стал частью процесса подготовки расписания: предварительную неделю можно было быстро прогнать через систему и найти пересечения до публикации.

## Что было слабым

- Архитектура росла вокруг срочных задач, а не вокруг заранее продуманной модели.
- В коде много глобального состояния, дублирования и магических чисел.
- Конфигурация была слишком близко к коду.
- PHP-интерфейс смешивал SQL, HTML и бизнес-логику.
- Веб-часть слабо защищена по современным меркам: нужны prepared statements, строгая валидация ввода и HTML-экранирование по контексту.
- Тесты частично завязаны на состояние живой базы.

## Главный вывод

Главная ценность проекта была не в чистоте кода, а в том, что он перевел реальный институтский процесс из бумажно-Excel-режима в цифровой. Это был проект самоучки, который учился на работающей системе и постепенно закрывал реальные проблемы пользователей.
